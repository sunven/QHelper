# 网页总结后的连续对话
Status: implemented

## 目标

用户生成网页总结后，在同一侧栏围绕该网页持续追问，后续问题可以承接前面的总结与问答，例如“展开第二点”“作者给了哪些证据”“接着说”。长网页的后文也必须可问，长对话尽量保留早期信息。

## 对话与正文

- 总结作为首条 AI 消息，后续按顺序展示用户问题和 AI 回答。输入框固定在底部，回答逐步显示，保留复制能力。
- 首版从总结开始，不提供跳过总结直接提问的流程。首条总结停止或失败后，只要已有可见的总结文字，就可以继续追问；没有总结文字时先重试总结。
- 回答以网页正文为依据，允许常识性补充解释，但必须与原文区分；原文没有的信息明确说明。首版不增加联网搜索。
- 一段网页对话固定使用开始总结时的网页正文快照。切换标签、导航、关闭原网页标签或原网页内容变化，不改变已有对话的依据。
- 界面清楚显示对话来源。只有用户主动“重新读取并开始新对话”或对另一页开始总结，才更换正文依据。
- 完整正文指开始总结时已加载的完整文字正文，不自动滚动加载、翻页、打开文中链接或识别图片。

## 开始、恢复与替换

- 配置齐全时，从 popup 或右键点击“总结网页”就是明确的开始指令，可以直接生成总结。配置缺失时先完成配置，不发送正文。
- 如果当前对话来自同一标签页且网址未变，重复点击该页的“总结网页”只恢复对话，不重新读取或重复请求。要使用网页的新内容，须显式重新读取。
- 普通重开侧栏只恢复已有对话，不自动继续请求。保存 API 配置本身也不发送内容。
- 每个浏览器窗口只保留一段当前对话，不提供历史会话列表。
- 对另一页开始总结或主动重新读取前，提醒将替换旧对话，用户确认后再开始。替换后的旧对话不提供恢复入口。
- 一次明确的总结、提问、继续或重试操作，可以包含完成该操作所需的分段阅读和对话压缩请求，无需逐次确认。

## 完整长文与长对话

- 移除现有只取正文开头 16,000 个字符的行为，完整已加载正文保留为本次对话的快照。
- 全文过长时允许分段阅读后汇总，不能因单次请求放不下而丢弃后文。用户接受相应的额外等待时间与 API 请求数。
- 追问时依据问题回看相关原文，必要时通读各段；处理长文不能导致末尾独有的信息不可问。
- 较早问答自动压缩成对话记忆，以尽量保留早期事实与约定；不逐次询问用户，也不直接只留下最近几轮。
- 压缩不删除可查看的完整聊天记录，界面显示简短状态，不承诺逐字记住旧问答。
- 压缩失败时保留当前问题并允许重试，不悄悄丢弃早期问答。对话记忆不替代网页正文快照。

## 中断、重试与配置变更

- 停止或失败后，已经生成的半段回答保留展示，也进入后续上下文；同时向用户和模型明确其未完成状态。
- 用户可以继续追问“接着说”。重试则重新回答同一个问题，用新回答替换旧半段，不追加并列答案。
- 生成中关闭侧栏时停止当前生成，保留已显示内容；不在后台继续生成。重开后用户可以重试或继续追问。
- 更换接口或模型时保留当前对话，下一次主动发送使用新配置，并明确显示所用接口和模型；已经发出的请求继续使用发起时配置。
- README、隐私说明和配置界面的相关文案须与实际触发规则一致，说明用户指定的接口会按操作需要接收网页正文及对话相关内容。

## 生命周期与清除

- 对话仅在本次浏览器使用期间保留，关闭再打开侧栏仍可继续；不做跨浏览器重启的长期保存或跨设备同步。
- 关闭原网页标签后，仍可依据已保存的正文快照对话。
- 关闭整个浏览器窗口时，清除该窗口的对话。不同窗口的对话相互独立。
- 侧栏提供“清除对话”，停止正在进行的请求，并删除该对话的正文快照、完整问答和压缩记忆。

## 验收场景

1. 总结后连续提出“展开第二点”“其中作者给出的证据是什么”，回答能够承接前面的总结与问答，并区分原文与补充解释。
2. 首条总结只产生半段后停止，界面标明未完成，用户可以追问；尚未产生总结文字时则先重试总结。
3. 在 A 页开始对话后切到 B 页、在原标签中导航或关闭原标签，继续追问仍依据 A 页快照，且界面明确显示 A 页来源。
4. 原页正文发生变化后，重复从同一标签、同一网址的总结入口进入，只恢复旧对话；主动重新读取并确认替换后，开始使用新正文的对话。
5. 从另一页发起总结，确认替换前仍保留原对话；确认后开启新对话，不混入旧页问答。
6. 长文末尾含有开头没有的事实时，可以针对末尾提问；全文过长时通过分段处理覆盖后文，不再受原有 16,000 字符截断影响。
7. 自动压缩旧问答后，完整记录仍可查看，后续问答尽量保留早期事实与约定；压缩失败时保留当前问题并提供重试。
8. 回答停止或失败后，半段内容进入后续上下文且保留未完成状态；重试同一问题替换原回答，不留下两份并列答案。
9. 生成中关闭侧栏，请求停止；重开后恢复已显示内容且不自动请求。用户可手动重试或继续。
10. 更换接口或模型不会自动请求或清空对话；下一次主动发送使用新配置，进行中的请求仍使用发起时配置。
11. 两个浏览器窗口各自保留自己的当前对话；关闭其中一个窗口只清除该窗口对话，重启浏览器不恢复对话。
12. 清除对话会停止请求，并清除正文、问答和记忆；之后重开侧栏不会恢复这些内容。

## 实现边界

- 每段原文按最多约 5,000 字符拆分；长文每次追问都会遍历原文各段，必要时逐层合并笔记，因此会增加请求数与等待时间。
- 上下文预算使用字符估算，无法覆盖所有兼容接口的 token 限制；接口拒绝、压缩失败或输出超限会明确报错，不静默截掉原文或旧问答。
- 单次问题限 4,000 字符，超出时保留输入并提示缩短。可见问答不因上下文压缩而删除，但压缩记忆和分段笔记可能丢失细节。
- 完整快照及问答受浏览器会话存储配额约束；保存失败会提示，不转存为长期记录。首次快照保存成功后才开始调用接口。
